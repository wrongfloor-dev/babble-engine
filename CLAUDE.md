# Babble Engine

Gibberish / fictional speech generator for games. Plain HTML + vanilla JS, no build step, no dependencies.

## Layout
Everything that goes online lives in `site/` (Cloudflare Workers static assets, `wrangler.jsonc`). `dossier/`, `metingen/`, `tests/` and this file stay out.
- `site/index.html` – markup for all views (make, my voices, studio, script, dialogs)
- `site/src/styles.css` – design tokens and styles. Look (redesign D, 2026-10-25): warm paper and ink outlines with a hard shadow, light by default with a dark variant; per style `body.e-*` sets `--accL/--accD` (accent, 5:1 or more with its text colour) and `--tintL/--tintD` (stage); Figtree UI font, Bagel Fat One for the logo, names and panel headings. Make screen: style cards with a mini critter (`MINI` in app.js), voices, then line and stage side by side at one height, player strip fixed at the bottom of the stage, settings below (this voice / all styles). Fonts are self-hosted in `site/fonts/` (woff2, SIL OFL; license files next to them)
- `site/src/engine.js` – all audio synthesis and analysis, no DOM. One source for the tool and the web module: loads as a plain script (global `Babble`), as CommonJS (`module.exports` at the bottom) and from `babble.mjs`.
  - `tokenize`, `prosody`, `renderSynth` (formant synthesis), `renderSample` (own-voice playback), `renderTone` (Soft Tones + Talking Instruments)
  - Bloopa Doopa (2026-10-26, replaced the Simlish-like Vemmo; internal id stays `vemmo` so links, characters and `style: 'vemmo'` keep working): the cartoon language of De Workshopbende, after its language guide v3. `INTENTS` (per intent: onsets, endings, tricks jump/rhyme/sing/plain, closer chance, interjections, anchors), `ANCHORS` (7 fixed words with their melody `mel`), `vemmoClip`, `bloopaWord`. Word filter `NOWORD` + `BADPART` (Dutch and known English words, rude words, other characters' catchphrases). Clusters (bl, pl, fl, kl, kr) are two consonants in `buildPhones`; with an own voice `pickGrain` uses the first. Tempo ×1.25 in `styleOpts`. Lengths: short about 0.5–1.2 s, medium 1–2.5 s (Bram slower on purpose). Other styles bit-identical (396 fingerprints).
  - Extra voice styles: `PALETTES` + `paletteLang` (Grumble, Gizmo, Sprite, Spooky Whisper, Babytalk), `babyfy`, `postFX` (grumble, gizmo, sprite, radio)
  - Styles added in 1.2.0 (2026-10-26): Name Talk (`nameSyls`, `nameTalk`, option `name`), Grunts & Barks (`BARKS`, `barkToks`, tokens carry `mel` + `hold`), Spooky Whisper (`ghostFX`: syllables reversed + reverb), Text Blips (`renderBlips`), Droid Chirps (`renderDroid`), Kazoo (a `renderTone` kind in Talking Instruments). `textToks` is the one text-to-syllables step for the tool, the studio preview and the module. All other styles stayed bit-identical (396 fingerprinted renders).
  - Styles and voices (2026-10-25, moved from app.js): `EMETA`, `ENGINE_ORDER`, `ENGINES`, `FX`, `wetFor`, `roomIR`. `styleOpts` + `renderStyle` are the render path (Echo Folk mixes four renders there); app.js `opts()`/`render()` call them. Moved bit-identical: 94 reference renders matched.
  - Seed: every noise call goes through `RND` (Math.random by default). `Babble.render` swaps in a seeded generator for one call, so the tool's sound is unchanged.
  - Web module API (`Babble`, version `BABBLE_VERSION` = `package.json`): `render(text, options)` → `{pcm, sampleRate, duration, syllables, style, voice}`, `toWav`, `play` (browser, with room), `styles`, `loadVoice`. Own voice (1.1.0, 2026-10-26): the Export button in Voices & characters downloads `<name>.babble-voice.json` (`voiceToFile`: every grain as base64 16-bit PCM plus its labels `c v pos f0 loud`, and the recording sample rate); `loadVoice` reads it, render option `ownVoice` (+ `steady`) uses it, `grainsAt` resamples to the render rate. Checked: module render of an exported voice matches the app within 16-bit rounding. English mood names map to the Dutch keys in `MOODS` (`MOOD_ALIAS`). `site/src/babble.mjs` re-exports it as an ES module, `site/src/engine.d.ts` has the types, `package.json` lets people `npm i github:wrongfloor-dev/babble-engine`. Docs: `README.md`.
  - Studio: `buildScript`, `studioSchedule`, `analyzeScriptRecording`, `splitChunk`, `estimateF0`, `makeAmbient`
  - Recording rounds (2026-10-25): `basis` (every consonant × a/e/i/o/u, 23 lines, 92 sounds, ~1:35) for a new voice, `extra` (diphthongs ai/ou/ay, 10 lines, ~0:42) added later to the same voice from My voices. Together they cover every sound the voice styles ask for. `algemeen`/`vemmo` stay only so older voices and uploads keep working. Vowels with the same `VSPEC` (a=ah, i=ee, u=oo, ay=ei) count as the same sound in `pickGrain`. More optional rounds (2026-10-26), added from My voices like `extra`: `bloopa` (11 lines: the clusters bl pl fl kl kr gr br fr with every vowel, plus dra, dree, hee, heh; label `k` = ''; ~0:41; the first version recorded whole syllables like flohp, voices that have those keep using them), `ends` (9 lines: every vowel with every end sound p b k m n l r, like a CVVC voicebank, label `tail`; ~0:34; `renderSample` plays a syllable without a recorded ending for 60% and cross-fades into the ending, retuned to the end note and matched in loudness (`tailFor`, `tailStart`, `vowelLevel`); `splitChunk` with `vc` moves each cut from the closure of a p or k to the start of the next vowel, so the burst stays with its sound) and `barks` (the 31 barks of Grunts & Barks, one whole sound per line, label `bark`; ~1:21). `pickGrain` uses such a syllable when start and vowel match: the exact ending first, else one of the same kind (`CODA_CLASS`: bib uses bip), else the version without ending (krik uses kri); `plainGrains` keeps them out of everything else; `renderSample` plays a recorded bark whole. Voice flags `extra`/`bloopa`/`ends`/`barks`. Any round recorded into a saved voice replaces only the sounds it brings (`mergeRound`, by label); "Redo basic round" uses that. Line edges: `soundSpan` keeps the soft consonants before the first vowel and the fade after the last (the old 8%-of-peak trim cut the k of a line-initial kah, measured 2026-10-26). A voice without these rounds renders sample-identical (checked against the committed engine).
  - Own voice pitch shift: a PSOLA shift that keeps length and colour was tried (2026-10-26) and removed: Raoul found it buzzy, too long and less cute than the resampled sound. Classic resampling stays, so a voice set far above the recording gets shorter syllables; recording in the character's own pitch is the fix.
  - Own voice pitch: `pitchTrack` follows each syllable's pitch every 10 ms; `renderSample` option `steady` (0–1, slider "Pitch steadiness", `bm.steady`) holds it on the melody. Without it the output is unchanged.
- Variants and characters (2026-10-25): per style, `cur()` is the latest result and `SV()` the variants saved with "+ Save variant" (each keeps its settings; clicking one plays it and restores them, × removes it; session only). "Save as character" stores style, voice, emotion, sliders, variation (`salt`/`take`) and language seed in `localStorage` `bm.chars`; characters show under Voice and in My voices. Keep UI copy short.
- Use in your game (2026-10-26): `site/game.html` (/game, in the sitemap) shows how to load the web module, speak a line, sync syllables and use an exported voice. On the make screen a round "‹/›" button next to Download (name "Use in your game" as aria-label and hover title; `gameCode()` in app.js) opens a dialog with the module call for the current settings: only options that differ from the voice, `seed` = `st.langSeed` for the made-up-language styles, `ownVoice` + the file name Export gives. The tool has no fixed seed, so the code gives the same voice and settings, not the identical take. GitHub icon in the header, "Use in your game · GitHub (MIT)" in every footer. /game: four short steps, Copy inside each code block (`src/game.js`), the AI-assistant prompt folded under "Show prompt" (self-contained API summary); `llms.txt` lists the web module API and every style and voice id. Update both when options, styles or voices change. 404 page: Fern looking for the page, "Hear Fern" plays a line through the real engine (`src/404.js`).
- `docs/art/`: the README pictures. SVG with the site fonts embedded, made by `node docs/art/make-art.cjs` (run it again after changing styles, voices or the critters in app.js); `tool.png` is a screenshot of the tool.
- Studio prepare screen (2026-10-26): one numbered checklist, Microphone → Listen → Practice (optional) → Record; a step ticks off when done (`prepSteps`: mic granted, example played, practice finished) and the first open one is highlighted. Settings fold under Record; the no-mic route is one line at the bottom. The Prepare/Record/Check bar has no numbers so it doesn't compete with the checklist.
- `site/src/app.js` – UI: i18n (EN/NL in `STR`), make screen, voices storage (IndexedDB `babble-machine`/`voices`: the old name is kept on purpose so voices saved earlier stay available), studio (mic, prompter, recorder), script (section 5)
- Script in the Studio, steps 1–4 of `dossier/bouwbrief-script.md` (2026-10-27): nav item Script (`#script`), `#viewScript` under the main header. Layout is design A4 (`dossier/ontwerp.md`, built 2026-10-27; the view uses the full width via `body.wide`): header with the title as its own field, a ⋯ menu (rename, duplicate with its takes, new, language of the lines, delete) and "Scripts (n)" to switch; left the overview (scenes with x/y and a ⋯ menu: rename, up/down, delete; characters with x/y, + adds one, a click opens its settings; filter "Only to record"); middle the script as a document (scenes as headings with a ⋯ menu and "x of y recorded", each line reads as text with status badge ✓/↻/○/♪ and ▶; one line at a time opens for editing: character, direction, text, Speak myself, Choose file…; Enter adds a line, Backspace on an empty line removes it, arrows at the start/end of the text go to the line before/after, Esc closes it, drag by the number or arrow keys on it / Alt+arrows in the text); right the prompter, the one dark surface (line before, current line big, next line of the same character, keys as key caps, state pill blinks while listening, Big = whole window with F, Esc leaves) and the takes of the current line (one chosen, played dry; drop an audio file here). The dividers drag to resize (`bm.scOv`, `bm.scPm`). Deleting a scene with lines asks: merge into the scene before (`removeScene`) or delete everything. An audio file (Choose file… or dropped on the takes) becomes a take of the line or of its [part] (a babble line without one gets its whole text bracketed): decoded with `decodeAudioData`, `finishTake` (trim + -16.1 LUFS), stored with `file` = its name. Step 3, sound per character (`c.fx` = `{pitch, effect, room}`, set in the Characters dialog with presets Plain/Radio/Robot/Fairy/Troll/Giant/Tiny/Hall, `FX_PRESETS`): pitch in semitones by resampling (`pitchShift`; the dialog says higher is also faster), one existing `postFX` effect as it is (radio, gizmo = Robot, sprite = Fairy, grumble = Troll; no ghost: `ghostFX` needs syllable marks a take doesn't have), then levelled to `TAKE_LUFS` again (`applyFx`); the room (`ROOM_WET` none/small/big over `roomIR`) is mixed in offline (`scTakeBuf`, cached per take and setting). Non-destructive: the stored take never changes. Applies to every playback of a recorded character's takes; for a babble character it is the sound of your own [part] (pitch and effect only; the room comes from the babble style). Characters dialog: name, fixed colour `cc0`–`cc7` (style accents), kind Real voice (`record`) or Babble (`babble`: `style`, `voice` incl. `own:<id>` for voice styles, `mood` = a `MOODS` key, or `intent` for Bloopa Doopa). Step 2: a babble line gets status ♪ Babble, never a take, and ▶ in the document; it renders with `Babble.render` (the web module, so a game gets the same sound from `babbleOpts`) with the line's own `seed` (new lines get one, `tidy` adds them to older scripts); "Other take" picks a new seed. In styles with a made-up language (sim, echo, radio) the seed also picks the language, so lines of one character can differ in sounds: the module has one seed. Cue: in a session, the babble lines right before your line in its scene (`cueBefore`) play first (status Speaking, output meter, prompter shows them; Skip skips), then listening starts; the take starts no earlier than that moment and listening waits 0.4 s for the room. Record on a babble line starts at the next line that needs a take (`nextRecord`). A hint suggests headphones when a script has both kinds. Mixed line (Raoul, 2026-10-27): a babble line can have one part in [square brackets] that you speak yourself ("Speak myself" wraps the selection, or the word at the cursor, widened to whole words: `markPart`; a frame behind the text field shows it): that part gets takes and status like a recorded line (`recText`, `partsOf`), the prompter follows only that part and shows the babble words in grey, the babble before it plays as the last cue, and ▶ plays babble before (seed+1) + the chosen take + babble after (seed+2). A mixed line is not a cue for the next line. Profiles: the Voice menu of a babble character lists the saved characters from the make screen (`CHARS`); choosing one copies style, voice, mood and sliders (`c.sl`, passed to the module as pitch/speed/expression/throat/breath/brightness) into the script character. One hands-free session: Record (or Space) listens, a take starts at the first sound (0.35 s pre-roll), ends on the pause after the line, is trimmed and levelled, and the prompter moves to the next line of that character that still needs a take; Space during a take ends it, in waiting stops; Esc stops (a take in progress is kept). Status per line with icon and text: ○ to record, ✓ recorded, ↻ text changed (the take keeps its text). Speech recognition only on the device (`SpeechRecognition.available/install` with `processLocally`; never the server version); otherwise the prompter follows the tempo and says so. `site/src/script.js` (`BabbleScript`, pure, also CommonJS): model, scenes, move/drag, status, `nextFor`, syllables (`sylCount`), `alignWords`, `trimTake` (soundSpan + 50 ms before / 100 ms after, 10 ms fades), `loudness` (BS.1770, checked: full-scale 997 Hz sine = -3.01 LUFS), `levelTake` to `TAKE_LUFS` = -16.1 LUFS (median of 280 babble renders, every style and voice × 4 lines, measured 2026-10-27; peak capped at -1 dBFS), tempo follower (`FOLLOW`: start at 4× the noise floor, end after 0.8 s pause once 60% of the line's voiced time is in, give up after 3 s, "too short" under 50%; voiced seconds per syllable learned per character, start 0.3; a pause of 0.3 s near a comma, full stop or the line end puts the marking there and re-estimates the tempo for the rest of the line, because the marking drifted 2–5 syllables behind by the end of a line: measured 2026-10-27 by replaying Windows TTS lines with and without room echo through the follower, after Raoul saw it stall on his second Dutch run). Those follower thresholds are first values tested only with a fake microphone: tune them with Raoul's real recordings. Storage: IndexedDB version 2 adds `scripts` (whole script) and `takes` (Float32Array audio, index `script`); `voices` untouched, upgrade tested with a version 1 voice.
- Script import/export (step 4, 2026-10-27): ⋯ › Import… / Export… and "Export" in the script header. Script file `<title>.babble-script.json` (`toFile`, `parseFile` reads JSON or plain text `# Scene` / `Name (dir): text`, `planImport` + `applyImport` sync on line id, else character + text; characters by id, else name). The import dialog shows new/changed/unchanged first; lines not in the file stay unless "delete" is ticked (their takes go too); a changed text becomes ↻ by itself. Export › For your game: stored zip (`makeZipN`) with `<line id>.wav` per line (takes through `scTakeBuf`, babble with the style's shelf + room via `scBake`) and `script.json` (`babble-script-export`: babble options with seed, syllables for pure babble lines, `file:null` without a take). Backup: script file + `takes.json` + `takes/<id>.wav`; importing a backup zip (`readZip`, `wavPcm`) restores it as a new script. Audio files named `<line id>.<ext>` become takes of that line (`scTakeFromFile`). Per line: ⤓ in the prompter downloads one WAV (`scDlLine`, `<line id>.wav` like the zip; a take that is not chosen gets `-take<n>`). The chosen take (the one that goes into the export) is a green check button (`aria-pressed`) plus a "Chosen" tag; clicking the chosen one again chooses none (the line is then to record and left out of the export). A new take is chosen. On a recorded line Record reads "Another take" (`scAgain`): it records that line once more and stops there instead of moving on. Prompter text size A−/A+ (`PMZ`, `--pmz`, `localStorage` `bm.pmSize`). The footer spans the full width on the Script screen. Format documented in `llms.txt`, README and /game.
- `addons/babble_engine/` – Godot 4 addon (phase 2, 2026-10-26): `babble_engine.gd`: a GDScript port of engine.js, `BabbleEngine.render(text, options)` with snake_case options (`sample_rate`). Must give the same samples as the web module: same RNGs (`rng` xorshift, `mulberry` for noise), JS rounding (`js_round`), Float32 where JS uses Float32Array. Errors: `push_error` and an empty Dictionary (no exceptions in Godot). Done (2026-10-26): all 16 styles, own voice (`load_voice`, `render_sample`, including the lowpass cache per sound that makes a render depend on earlier ones, same as JS), and `babble_speaker.gd` (`BabbleSpeaker`, an AudioStreamPlayer: renders on WorkerThreadPool, signals `line_started`, `syllable(index, text)` corrected for output latency, `line_finished`; option `babble_seed` because `seed` shadows a built-in) and `demo/demo.tscn` (UI built in demo.gd: style, voice, mood, a mouth that opens per syllable). The voice, intent, anchor, bark and palette tables are generated from engine.js (scratchpad script, not in the repo): change them in engine.js and port by hand. GDScript pitfalls met: lambdas copy locals (append in place), Packed arrays are copy-on-write (assign filter results back), `len` shadows a built-in. Speed: about 15× slower than the web module. `tests/godot.mjs`: 258 cases sample for sample (max difference 1.2e-7) plus a BabbleSpeaker run; headless audio signals syllables ~70 ms early (no output latency there); in the editor with real audio Raoul found sound and mouth timing right (2026-10-26). Download: `.github/workflows/godot-zip.yml` zips `addons/babble_engine` (+ LICENSE) on every `v*` tag and attaches it to the release as `babble-engine-godot.zip` (fixed name, so `releases/latest/download/babble-engine-godot.zip` is always the newest; linked from README, /game, llms.txt; first in 1.3.1). ## Rules
- Don't change synthesis algorithms for visual work.
- UI copy goes through `t()` with keys in both `STR.en` and `STR.nl`.
- One audio player at a time: always play through `pPlay()` / stop with `pStop()`.
- Studio capture runs on the audio thread (`site/src/rec-worklet.js`, AudioWorkletNode); `ScriptProcessorNode` is only a fallback. It dropped and repeated samples on a busy page (crackle, measured 2026-10-25). The mic is taken raw: `echoCancellation`, `noiseSuppression` and `autoGainControl` off. "Your recording" plays dry (straight to `ctx.destination`).
- Own voices only work with engines where `EMETA[e].rec` is true (all voice styles; not Soft Tones or Talking Instruments).
- WAV export: a plain `.wav` Blob download. Inside a claude.ai artifact (`window.claude` present) it goes through the `downloads` capability instead, zipped (that allowlist has zip, not wav).
- Strict CSP (`site/_headers`, enforced since 2026-10-25): no inline `style`/`<script>`/`on…=` in HTML, no requests to other hosts. Setting `el.style.x` from JS is fine. JSON-LD (`application/ld+json`) is allowed.
- `site/sitemap.xml` lists every public page; a page goes online only when its integration exists.

## Run / test
- Serve `site/` locally: `npx wrangler dev` (applies `_headers` and the 404 page) or `python3 -m http.server -d site`, then open http://localhost:8787 or :8000 (microphone needs http(s), not file://).
- Build check, no dependencies: `node tests/check.mjs` (STR keys EN = NL, banned writing patterns in STR and in the style and voice descriptions in app.js and engine.js, links, sitemap, strict-CSP readiness, headers).
- Godot parity: `GODOT=<path to Godot console exe> node tests/godot.mjs` renders the same lines in a temporary Godot project and the web module and compares sample by sample (`tests/godot/runner.gd`).
- Engine check: `node tests/engine.mjs` (every voice renders without NaN, syllable times in order, same seed same sound, clear errors for bad options, valid WAV, `babble.mjs` exports, version = `package.json`). Both: `npm test`.
- Script: `node tests/script.mjs` (in `npm test`). Browser: `PLAYWRIGHT=<path to playwright-core> node tests/script_browser.mjs` (Chrome, fake microphone fed with a babble WAV; IndexedDB upgrade keeps a version 1 voice, task flows 1, 3 and 4 (babble line plays, plays as the cue, take after it), a mixed line, an audio file as take, scene merge, duplicate, sound per character, export/import/backup, Big, reload, keyboard move, 360 px; not in `npm test`, the repo has no dependencies).
- Older browser tests (Playwright, Chromium with a fake microphone): `tests/make_screen.py`, `tests/studio.py`. **Out of date** (2026-10-25): they target an older UI (`#voiceSel`, `brabbel.html`, `pw.py`) and a single-file `t2.html`; rewrite them against `site/` via a local server.
- The fake microphone is a test tone, not a voice: real voice recording still needs a manual check.
